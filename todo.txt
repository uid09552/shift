Feature ideas: shift / roster planning (no Zeitkonto / time accounts)
=====================================================================
Already exists (not repeated below): optimizer with coverage first, rotations,
wishes and the wish window, swaps, short-notice replacement, personal limits,
public holidays, fairness page, skill levels, weekly hours, plan check and fix,
audit log.

HIGH VALUE
----------
[ ] Roster lifecycle: draft -> published -> locked per month/workstation.
    - Publish deadline (e.g. 4 weeks ahead), freeze window
    - After publish: every change is tracked and shown to the people affected
    - Re-solve after publish penalises changes against the published roster
      (keep things stable, change as few people as possible)
[ ] Leave / vacation requests with approval (planner/admin)
    - Max people absent at once per workstation/capability, blackout periods
    - Approved leave becomes unavailability; the optimizer sees pending leave as soft
    - Annual leave planning view (whole year, per team)
[ ] Open shifts / shift bidding
    - Short slots (from message / staffing gaps) posted as open shifts
    - Qualified, rule-compliant employees volunteer; planner assigns
    - Reuses the agent's replacement ranking
[ ] Skill-mix rules per shift/workstation
    - "at least 1 x level >= 3 per shift", "max 2 trainees"
    - Trainee must be paired with a mentor (same shift + workstation)
    - Must / must-not work together (pairing constraints)
[ ] Labor-law rule set (ArbZG) as a selectable profile
    - Max 10 h/day, 48 h/week average over N weeks, breaks
    - Special groups: minors (JArbSchG), pregnancy (MuSchG: no nights/Sundays)
    - Plan check reports legal violations separately from soft goals
[ ] Notifications: email / push for roster published, changes to my shifts,
    swap/leave status, open shift offered

PLANNING QUALITY
----------------
[ ] Long-horizon fairness: carry night/weekend/holiday counts across months
    (history beyond 14 days), alternate Christmas / New Year fairly
[ ] Recurring availability (not just wishes): "only early shifts", "never Wednesdays",
    part-time on fixed days; hard or soft per employee
[ ] Time-of-day demand: staffing curve per hour instead of per shift;
    optimizer chooses shift types / split and overlap shifts to cover it
[ ] Float / pool staff: employees shared across workstations or departments,
    with a "home" station preference and lending between teams
[ ] On-call / standby duties (Bereitschaft, Rufdienst) as their own duty type
    with own limits and rest rules
[ ] Scenario planning: what-if (sick wave, closed ward, +2 hires) without
    touching the real proposal; capacity forecast months ahead (staffing gaps
    from leave + contracts)
[ ] Plan-quality KPIs per run: coverage %, wishes met %, rule breaks, fairness
    spread, changes vs published; trend over months

CERTIFICATIONS
--------------
[ ] Capabilities with expiry dates (e.g. resuscitation training); warn in advance,
    the optimizer stops using an expired capability

OUTPUT / SELF-SERVICE
---------------------
[ ] iCal feed per employee (subscribe in phone calendar)
[ ] PDF / Excel export of the roster (per ward, wall print layout)
[ ] Mobile-friendly "my shifts" view: next shifts, open shifts, swaps, leave
